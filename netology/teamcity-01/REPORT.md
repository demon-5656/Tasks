# TeamCity

## Подготовка стенда

Для задания подготовил отдельный стенд в Yandex Cloud:

- TeamCity Server;
- TeamCity Build Agent;
- отдельную VM для запуска playbook.

Server и Agent находятся в одной сети. Агент подключается к серверу по внутреннему адресу, поэтому не зависит от внешнего IP.

TeamCity Server доступен по порту `8111`. Build Agent запущен и ожидает завершения первичной настройки сервера, после чего его можно авторизовать в интерфейсе TeamCity.

## Что будет сделано дальше

После завершения первоначальной настройки TeamCity план такой:

1. Сделать fork учебного репозитория и создать проект в TeamCity.
2. Выполнить autodetect конфигурации и сохранить нужные шаги.
3. Настроить Maven-сборку:
   - в `master` — `mvn clean deploy`;
   - в feature-ветках — `mvn clean test`.
4. Добавить Maven settings для подключения к Nexus и проверить публикацию артефакта.
5. Перенести конфигурацию сборки в репозиторий.
6. Создать ветку `feature/add_reply`, добавить метод с репликой, содержащей `hunter`, и тест на него.
7. Проверить автоматический запуск сборки после push и выполнить merge в `master`.
8. Настроить публикацию `.jar` в артефакты сборки и повторно проверить master-сборку.

## Итог на текущем этапе

Инфраструктура для TeamCity готова: сервер, агент и отдельная машина для playbook подняты и доступны. Следующий шаг — закончить первичную настройку TeamCity и перейти к настройке CI-конфигурации.
